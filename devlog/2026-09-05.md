## 发布包 QtWidgets DLL 加载失败修复

- [x] 定位 `dist` 版 EXE 启动报 "DLL load failed while importing QtWidgets（找不到指定的程序）" 的根因。
- [x] 修复 `build.py`：打包后清理会遮蔽系统运行库的 DLL 并在 `validate_package` 中拒绝回归。
- [x] 重新生成目录包与 ZIP，EXE 离屏启动验证和 ctypes 加载验证均通过。
- [x] 全量回归测试 `116 passed`。

### 根因

- PySide6 6.11 的 `Qt6Core.dll` 以普通符号名（`ucnv_open` 等 20 个）依赖系统 `icuuc.dll`，PySide6 轮子本身不携带 ICU，依赖 Windows 系统的 ICU 转发器提供。
- 构建机的 `C:\Users\cat\.cache\codex-runtimes\...\poppler|libheif` 目录中存在 conda 风格 ICU 78 / UCRT 副本，被 PyInstaller 沿依赖搜索收进 `_internal` 根目录。
- 该 ICU 78 的符号带 `icu_78` 版本化重命名，3027 个导出中不含 Qt6Core 需要的任何一个普通符号；运行时它又先于 System32 被找到，导致 `ERROR_PROC_NOT_FOUND (127)`，`import QtWidgets` 必然失败。beta_3 时代 PySide6 版本不依赖 ICU，因此没有暴露。

### 修复方案（build.py）

- 新增 `SHADOWING_BINARY_PATTERNS` 与 `_remove_shadowing_binaries()`：打包后删除 `_internal` 根目录的 `icuuc*.dll`、`icudt*.dll`、`icuin*.dll`、`ucrtbase.dll`、`api-ms-win-*.dll`，统一交由 Windows 系统提供（与 PySide6 官方部署模型一致）。
- `validate_package` 增加对应拒绝规则，防止今后构建回归。
- 根目录保留的 `libcrypto-3-x64.dll` / `libssl-3-x64.dll` 来自 poppler 目录但经验证不影响加载且 PySide6 轮子不自带 OpenSSL，予以保留。
